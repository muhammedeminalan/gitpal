## Shared rules (apply to every module)

Read first: `docs/PROJECT_SPEC.md` (sections 3, 4, 7, 11, 12, 17), `DECISIONS.md` (A-007 … A-020) and, in `internal/core/git`:
`runner.go`, `errors.go`, `localize.go`, `args.go`, `repo.go`, `gitconfig.go`, `gittest/gittest.go`, `runner_git_test.go`,
`runner_test.go` (for `fakeRunner`), `main_test.go`. Match their style.

### Conventions (binding)
- git is started ONLY through (*Runner).Run. Arguments are separate argv entries; never a shell, never string concatenation of user input into an option other than as the value part of a single "--opt=value" argument.
- `dir` parameters are the working tree root (see TopLevel). Paths given to and returned by the package are relative to it, with forward slashes (as `git status --porcelain` prints them).
- User-supplied paths: use pathspecStdin (args.go) when the git command supports --pathspec-from-file (git >= 2.30 must support it for that command), otherwise validate with checkPaths and pass them after "--". In both cases set Cmd.Env = []string{literalPathspecsEnv} so globs/pathspec magic are NOT expanded.
- User-supplied branch/remote/revision names: validate with checkName(value, ArgInvalid…) and place them after the endOfOptions argument wherever the git command accepts it (verify by test that a hostile value such as "--force" or "--output=/tmp/x" is refused and has no effect).
- Parse machine formats only (-z / NUL separated, --porcelain, explicit --format). Use splitNUL. Never parse human-readable output when a machine format exists.
- Output must not depend on the user's git configuration. Runner already passes `-c color.ui=never -c core.quotepath=false`; for your commands pass explicit flags that neutralize config that changes output or behavior (write tests that set the hostile config in the test repo and show the result is unchanged).
- Must work with git >= 2.30 (MinVersion). Do not use flags introduced later without a fallback; mention any flag you use that is newer than 2.25 and the version it appeared in.
- Must work on macOS, Linux and Windows: no shell, no POSIX-only assumptions in non-test code; tests that need chmod/symlinks/newlines-in-filenames must skip on Windows (runtime.GOOS).
- Errors: return the *Error from Run (optionally wrapped with fmt.Errorf("…: %w", err)); refuse bad input with *ArgError before running git. Error kinds are for explanation only — when a caller must KNOW a state (conflict, nothing staged), inspect the repository instead of matching stderr text.
- Never log or put file contents, diffs, tokens or credentials into error strings. URLs shown to callers go through redact().
- Secrets/safety: the safety layer (confirmation, backups) is milestone M2 and NOT your job. Your functions do exactly what they are asked.

### Collision rules (only when the modules are written in parallel)
- Create/edit ONLY the files listed for your module. Do NOT edit: errors.go, localize.go, args.go, runner.go, repo.go, gitconfig.go, any existing test file, internal/core/i18n/*, gittest/*, Makefile, .golangci.yml, DECISIONS.md, go.mod (no new dependencies).
- The public API listed for your module is yours; use exactly those names. EVERY OTHER new package-level identifier (types, funcs, vars, consts, test helpers), in both `package git` and `package git_test`, must start with your module prefix (given below), e.g. `statusParseHeader`, `statusTestRepo`. Test function names must start with Test<ModulePrefixCapitalized>….
- If you need a new ErrorKind or ArgCode, declare the const in your own source file (with a doc comment) and list it in your report; the integrator adds it to the tables and writes the TR/EN messages.
- You may use (not modify) everything in the foundation: Runner.Run, Runner.Head, Runner.TopLevel, Runner.ConfigGet, ExitCode, KindOf, splitNUL, pathspecStdin, checkPaths, checkName, networkCmd, literalPathspecsEnv, endOfOptions, redact, truncate. Do not depend on other modules' new API (they do not exist in your worktree); if you need a tiny piece of what another module provides, write your own prefixed unexported helper and mention the duplication in your report.

### Method: test first (project rule)
1. Write the tests first: integration tests against real git with gittest (package git_test, file <module>_git_test.go) and unit tests for parsers with literal fixtures (package git, file <module>_test.go). Tests only ever touch gittest temp repos with the isolated config — never real repos or the user's global config.
2. Run `go test ./internal/core/git/...` and see them fail (a compile failure for the missing API counts).
3. Implement. Re-run until green.
4. Edge cases you must cover where they apply: unborn branch (no commits), detached HEAD, file names with spaces / unicode (Turkish: "çalışma dosyası.txt") / leading dash / quotes / tab / newline (skip on Windows), nested directories, empty input, not-a-repository (KindNotARepo), hostile user input, hostile user git config.

### Done means (per module)
- `go test -race -count=1 ./internal/core/git/...` passes.
- `golangci-lint run ./internal/core/git/...` reports nothing (the only tolerated findings are "unused" for literalPathspecsEnv / endOfOptions when your module has no use for them). Format with `golangci-lint fmt ./internal/core/git/...`.
- Statement coverage of your own source files is >= 85% (`go test -coverprofile=/tmp/<prefix>.out ./internal/core/git/ && go tool cover -func=/tmp/<prefix>.out | grep <yourfile>`).
- Commit on the `m1-git-core` branch: `git commit -m "feat(git): <kısa Türkçe açıklama>"`. Do not push.

## Module briefs

### Module: status (spec 4.1, 4.2, 4.6 "devam eden işlem durumunu algılama")
Public API (use these names):
- `type FileState byte` with consts StateUnmodified '.', StateModified 'M', StateTypeChanged 'T', StateAdded 'A', StateDeleted 'D', StateRenamed 'R', StateCopied 'C', StateUnmerged 'U' — one column of porcelain v2 "XY".
- `type EntryKind string`: EntryChanged, EntryRenamed (rename or copy), EntryUnmerged, EntryUntracked, EntryIgnored.
- `type StatusEntry struct { Kind EntryKind; Path string; OrigPath string /* rename/copy source */; Index, Worktree FileState; Score int /* similarity for renames/copies */; Submodule bool }` with methods `Staged() bool`, `Unstaged() bool`, `Conflicted() bool`.
- `type BranchStatus struct { Head string /* branch name, "" when detached */; Detached bool; Unborn bool; OID string /* "" when unborn */; Upstream string /* e.g. "origin/main", "" if none */; UpstreamGone bool /* configured but missing on the remote side */; Ahead, Behind int }`.
- `type Operation string`: OpNone "", OpMerge, OpRebase, OpAm, OpCherryPick, OpRevert, OpBisect.
- `type Status struct { Branch BranchStatus; Entries []StatusEntry; Operation Operation }` with methods `Clean() bool` (ignored entries do not make it dirty), `Staged()`, `Unstaged()`, `Untracked()`, `Conflicted()` returning []StatusEntry.
- `type UntrackedMode string` (UntrackedAll default — every file listed individually, UntrackedNormal, UntrackedNone) and `type StatusOptions struct { Untracked UntrackedMode; Ignored bool }`.
- `func (r *Runner) Status(ctx context.Context, dir string, opts StatusOptions) (Status, error)` — `git status --porcelain=v2 -z --branch --untracked-files=…` plus the in-progress operation.
- `func ParseStatus(out []byte) (Status, error)` — parser for porcelain v2 with -z and --branch. Remember: with -z a rename/copy record is followed by a second NUL-terminated field holding the original path; header lines start with "# branch."; "(initial)" oid means unborn; "(detached)" head; a "branch.upstream" header without "branch.ab" means the upstream is gone. Unknown record types are an error (do not include file contents in the message).
- `func (r *Runner) InProgress(ctx context.Context, dir string) (Operation, error)` — detect merge / rebase (rebase-merge and rebase-apply; rebase-apply with an "applying" file is `git am`) / cherry-pick / revert / bisect by resolving the files with `git rev-parse --git-path …` (works in linked worktrees and with a relocated git dir) and checking they exist.
Hostile config to neutralize and test: status.renames=false, status.showUntrackedFiles=no, status.relativePaths, status.branch, status.short, core.quotepath (already), status.submoduleSummary, advice.*.
Integration tests must include: clean repo; modified, staged, staged+modified again; untracked files in nested directories; deletion (staged and unstaged); staged rename (git mv) with OrigPath; unborn repo; detached HEAD; ahead/behind against a bare origin (use gittest.NewBareRepo + gittest.Clone); upstream gone (remote branch deleted, fetch --prune); merge conflict (unmerged entries, Conflicted(), OpMerge); rebase stopped on conflict (OpRebase); cherry-pick stopped on conflict (OpCherryPick); revert conflict (OpRevert); awkward file names; ignored files only when asked; not a repository; a repository inside a linked worktree (git worktree add) reports its own operation state.

### Module: diff (spec 4.2 "Diff görüntüleme … binary dosya algılama"; M4 will send diffs to AI, M5 will stage hunks with git apply)
Public API (use these names):
- `type DiffOptions struct { Staged bool /* index vs HEAD (the empty tree when unborn); otherwise working tree vs index */; Commit string /* when set: the changes that commit introduced relative to its first parent, or to the empty tree for a root commit; Staged is ignored */; Paths []string /* limit to these paths */; Context int /* lines of context; 0 means git's default (3) */ }`
- `type ChangeType string`: ChangeAdded, ChangeDeleted, ChangeModified, ChangeRenamed, ChangeCopied, ChangeTypeChanged.
- `type LineKind byte`: LineContext ' ', LineAdded '+', LineDeleted '-', LineNoNewline '\\'.
- `type DiffLine struct { Kind LineKind; Text string /* without the leading marker and the trailing newline */; OldLine, NewLine int /* 1-based; 0 when not applicable */ }`
- `type Hunk struct { OldStart, OldLines, NewStart, NewLines int; Section string /* text after the second @@ */; Lines []DiffLine }`
- `type FileDiff struct { Path string /* new path; for a deletion the old one */; OldPath string /* set for renames and copies only */; Change ChangeType; Binary bool; OldMode, NewMode string /* e.g. "100644"; equal or empty when unchanged */; Similarity int; Hunks []Hunk }`
- `func (r *Runner) Diff(ctx context.Context, dir string, opts DiffOptions) ([]FileDiff, error)`
- `func (r *Runner) DiffRaw(ctx context.Context, dir string, opts DiffOptions) ([]byte, error)` — the unified diff text exactly as git printed it.
- `func ParseDiff(raw []byte) ([]FileDiff, error)` — parser for git's unified diff with the standard a/ b/ prefixes.
- `type FileStat struct { Path, OldPath string; Added, Deleted int; Binary bool }` and `func (r *Runner) DiffStat(ctx context.Context, dir string, opts DiffOptions) ([]FileStat, error)` using `--numstat -z` (binary files print "-\t-"; with -z a rename prints an empty path field followed by old and new path as separate NUL-terminated fields).
Requirements:
- Neutralize config: force `--src-prefix=a/ --dst-prefix=b/` (diff.noprefix, diff.mnemonicPrefix), `--no-ext-diff` (diff.external), `--no-textconv`, `--no-color`, explicit rename detection `-M` (diff.renames=false/copies), `--no-relative` if available in 2.30 (diff.relative) — verify version; diff.context/-U via the Context option only (pass an explicit -U always so diff.context cannot change it), diff.algorithm is harmless, diff.submodule → `--submodule=short`, diff.ignoreSubmodules, diff.orderFile (`-O/dev/null` is not portable — think about it), diff.interHunkContext → `--inter-hunk-context=0`, diff.wsErrorHighlight irrelevant, diff.suppressBlankEmpty (changes the context line marker for blank lines! handle a completely empty line inside a hunk as an empty context line), core.autocrlf/CRLF content (a line ending in \r keeps its \r in Text).
- Path parsing is the hard part. git C-quotes paths containing ", \, control chars (tab, newline) — with core.quotepath=false non-ASCII is left alone; quoted paths are wrapped in double quotes with C escapes (octal \NNN, \t, \n, \", \\). Prefer the unambiguous lines ("rename from/to", "copy from/to", "--- a/…", "+++ b/…"; "/dev/null" for the missing side). When a file diff has none of those (mode-only change, binary change, empty file added/deleted) fall back to the "diff --git a/X b/Y" header, which is ambiguous when names contain " b/": for non-renames both names are identical, so split at the midpoint the way git's own apply does. Note "--- a/file with space.txt" lines may carry a trailing TAB when the name contains whitespace.
- Binary detection: "Binary files … differ" (and "GIT binary patch" if present). A binary file has no hunks.
- Hunk header forms: "@@ -1 +1 @@", "@@ -0,0 +1,3 @@", "@@ -3,7 +3,8 @@ func name()". Compute OldLine/NewLine for every line. "\ No newline at end of file" is a LineNoNewline entry belonging to the preceding line.
- Staged on an unborn branch must work (everything shows as added). Commit must work for a normal commit, a root commit and a merge commit (first parent). Do not hard-code the SHA-1 empty tree id without thinking about SHA-256 repositories (compute it with git, or use a command form that needs no tree id).
- Paths filter goes after "--" with literalPathspecsEnv (git diff has no --pathspec-from-file).
- Combined diffs (--cc) and submodule log formats are out of scope; a submodule change is just a modified gitlink entry (mode 160000).
Integration tests must include: unstaged vs staged vs both; unborn staged; added/deleted/renamed(with edit)/copied?/mode change (skip on Windows)/binary (bytes with NUL)/empty file added; no newline at EOF on either side; awkward names (space, Turkish chars, tab, quote, leading dash, " b/" inside the name, newline — skip where the OS cannot create it); hostile config repo (diff.noprefix=true, diff.mnemonicPrefix=true, diff.external=/bin/false-like nonexistent program, color.diff=always, diff.renames=false, diff.context=0, diff.suppressBlankEmpty=true, diff.relative=true) gives identical parsed result; Paths with a glob-looking literal name ("*.txt" as an actual file name does not match other files); Commit for normal/root/merge; DiffStat incl. binary and rename; DiffRaw output can be fed back to `git apply --cached --check` successfully (proves it is faithful); invalid Commit value ("--output=x") refused with ArgInvalidRev and no file created; a large diff (few thousand lines) parses with correct line numbers. Unit tests for ParseDiff with literal fixtures for every header shape, plus malformed input returning an error rather than panicking (fuzz-ish table: truncated hunks, garbage header numbers).

### Module: stage + commit (spec 4.2 stage/unstage/discard/.gitignore shortcut, 4.3 commit, 4.8 restore)
Public API (use these names):
stage.go
- `func (r *Runner) Stage(ctx context.Context, dir string, paths []string) error` — stage modifications, new files AND deletions of exactly these paths (pathspecStdin + literal pathspecs). A directory path stages everything under it.
- `func (r *Runner) StageAll(ctx context.Context, dir string) error` — `add --all`.
- `func (r *Runner) Unstage(ctx context.Context, dir string, paths []string) error` — remove the paths from the index without touching the working tree. Must also work on an unborn branch (there `git restore --staged` cannot resolve HEAD; use `git rm --cached` semantics) — use Runner.Head to tell.
- `func (r *Runner) UnstageAll(ctx context.Context, dir string) error` — same for everything; born and unborn.
- `type RestoreOptions struct { Paths []string; Source string /* revision to take content from; empty = git's default */; Staged bool; Worktree bool /* when both are false, Worktree is implied, like git */ }` and `func (r *Runner) Restore(ctx context.Context, dir string, opts RestoreOptions) error` — `git restore`. Discarding working tree changes is destructive; the M2 safety layer will wrap this function, so it must do exactly what is asked and never delete untracked files.
- `func IgnorePaths(dir string, paths []string) error` — the ".gitignore'a ekle" shortcut: append the given repo-relative paths to <dir>/.gitignore as ANCHORED, LITERAL patterns (leading "/", glob metacharacters * ? [ \ escaped, leading "#"/"!" cannot occur after the "/" anchor, trailing spaces escaped), creating the file if needed, keeping existing content byte-for-byte, adding a missing final newline before appending, skipping patterns already present, validating with checkPaths. Verify in tests with `git check-ignore` that exactly the intended file is ignored (e.g. a file literally named "a*.txt" does not make "ab.txt" ignored) and that CRLF .gitignore files are not mangled.
commit.go
- `type SignMode int`: SignDefault (follow the user's git config — spec: "mevcut git config'e saygı göster"), SignAlways (-S), SignNever (--no-gpg-sign).
- `type CommitOptions struct { Message string; Amend bool; AllowEmpty bool; Sign SignMode }`, `type CommitResult struct { Hash string }`.
- `func (r *Runner) Commit(ctx context.Context, dir string, opts CommitOptions) (CommitResult, error)`:
  - the message goes in on stdin (`--file=-`) with `--cleanup=whitespace`, so lines starting with "#" survive and no editor is ever needed; an empty or whitespace-only message is refused with ArgError{Code: ArgEmptyMessage} before git runs. With Amend, an empty Message means "keep the existing message" (`--no-edit`).
  - "boş commit engelleme": when nothing is staged and neither AllowEmpty nor Amend is set, return an *Error with Kind KindNothingToCommit WITHOUT creating a commit. Decide this by inspecting the index (`diff --cached --quiet`, incl. the unborn case), not by parsing output (git prints "nothing to commit" on stdout).
  - hooks must run (never pass --no-verify). When the commit fails and classification says KindUnknown, and an executable pre-commit, prepare-commit-msg or commit-msg hook exists (resolve with `git rev-parse --git-path hooks/<name>`, which honours core.hooksPath), set the returned *Error's Kind to KindHookFailed; the hook's output must be available in Error.Stderr so the UI can show it (spec: "hata çıktısı kullanıcıya düzgün gösterilsin"). Test with real hooks (skip on Windows if needed) including a hook that prints multi-line output and one that modifies files and succeeds.
  - a missing identity must surface as KindIdentityMissing (use gittest.WithoutIdentity()).
  - unresolved conflicts in the index must surface as KindConflict (inspect state if stderr is not enough).
  - return the new commit's full hash.
- `func (r *Runner) HasStagedChanges(ctx context.Context, dir string) (bool, error)` — born and unborn.
- `func (r *Runner) LastCommitMessage(ctx context.Context, dir string) (string, error)` — full message of HEAD (for amend prefill); KindUnbornBranch-kind error when there is no commit.
- `func (r *Runner) RemoteContains(ctx context.Context, dir, rev string) (bool, error)` — whether rev is reachable from any remote-tracking branch, i.e. already pushed (spec 4.3 "amend: push edilmişse uyar", 7.2 rule 3). Use plumbing (`for-each-ref --contains`), rev after checkName.
Hostile config to neutralize/test: commit.gpgsign=true with a broken gpg.program (SignNever must still commit; SignAlways must fail because signing was really attempted; SignDefault follows config), commit.template, commit.cleanup=strip (a "# heading" line must survive), commit.verbose, commit.status, core.commentChar, core.editor / GIT_EDITOR (must never be invoked: point it at a program that fails and/or writes a marker file), add.ignoreErrors, core.autocrlf is the user's business (leave it).
Integration tests must include: stage one of two modified files; stage a deletion; stage a directory; stage a file literally named "*.txt" without staging "a.txt"; stage with thousands of paths (stdin path list, no argv limit); stage an ignored file (document the resulting error); stage nonexistent path → KindPathspecNoMatch; empty list → ArgNoPaths; path escaping the repo → ArgInvalidPath; unstage on born and unborn branch keeps working tree content; unstage a staged deletion / rename; restore worktree discards only the named file and keeps untracked files; restore --staged --worktree from a Source revision; Source "--bad" refused; commit happy path returns the hash that `rev-parse HEAD` shows; multi-line + unicode + "#"-line message preserved byte-for-byte (compare with `log -1 --format=%B`); empty message; nothing staged; AllowEmpty; amend with new message / keeping message; amend on unborn; hook rejection (KindHookFailed + output); commit-msg hook rejection; no identity; commit during a merge with unresolved conflicts; commit on detached HEAD works; RemoteContains before/after push (bare origin + clone) and for a hostile rev; LastCommitMessage.

### Module: log (spec 4.7 "log (graph görünümü, arama, yazara/tarihe/dosyaya göre filtre)", "commit detayı"; spec 6.2 needs the last 10 commit messages)
Public API (use these names):
- `type Commit struct { Hash, ShortHash string; Parents []string; AuthorName, AuthorEmail string; AuthorDate time.Time; CommitterName, CommitterEmail string; CommitterDate time.Time; Subject, Body string; Refs []string /* decorations such as "HEAD -> main", "origin/main", "tag: v1.0" */ }` with method `IsMerge() bool`.
- `type LogOptions struct { Revs []string /* revisions or ranges like "main..feat"; empty means HEAD */; All bool /* every ref */; Max int /* 0 = no limit */; Skip int; Author string; Grep string; IgnoreCase bool /* for Author/Grep */; Since, Until time.Time /* zero = unbounded */; Paths []string; Follow bool /* follow renames; only valid with exactly one path */; FirstParent bool; NoMerges bool }`
- `func (r *Runner) Log(ctx context.Context, dir string, opts LogOptions) ([]Commit, error)` — newest first. On an unborn branch with default revs it returns an empty slice and no error (use Runner.Head). Parents let the UI draw the graph; rendering a graph is M3 and not your job.
- `func ParseLog(out []byte) ([]Commit, error)` — parser for your own `-z --format=…` layout (fields separated by %x00, a fixed number of fields per commit; with -z git separates commits with NUL too — design the layout so a body containing any byte except NUL parses unambiguously, and a field-count mismatch is an error, not a silent misparse).
- `func (r *Runner) CommitInfo(ctx context.Context, dir, rev string) (Commit, error)` — one commit (KindRefNotFound-kind error when it does not exist).
- `func (r *Runner) RecentMessages(ctx context.Context, dir string, n int) ([]string, error)` — the full messages of the last n commits on HEAD, newest first; nil on an unborn branch.
Requirements:
- Dates in strict ISO 8601 (%aI/%cI) parsed with time.RFC3339, keeping the commit's own UTC offset.
- Revs each validated with checkName(…, ArgInvalidRev) and placed after endOfOptions; Paths after "--" with literalPathspecsEnv; Author/Grep values only as the value of a single "--author=<v>" / "--grep=<v>" argument (they are regexes for git — decide and document whether you pass --fixed-strings so a user typing "fix(ui)" or "[wip]" gets a literal search; a literal search is the safer default for a UI search box).
- Neutralize config: `--no-show-signature` (log.showSignature would inject gpg output), explicit --format (format.pretty), `--no-color`, decorations must not depend on log.decorate (use %D and make it deterministic: `--decorate=short`; consider `--decorate-refs` availability), log.follow, log.mailmap/mailmap (decide: raw names %an/%ae vs mailmap %aN — pick raw + `--no-mailmap` if 2.30 has it, document), log.date, i18n.logOutputEncoding (force UTF-8 with `--encoding=UTF-8`), log.showRoot irrelevant, notes (`--no-notes`), grafts/replace refs are the user's business.
- Body: everything after the subject line, without the trailing newline(s); Subject as git's %s. A commit with only a subject has Body "".
Integration tests must include: unborn; single root commit (no parents); linear history order; merge commit (two parents, IsMerge, NoMerges, FirstParent); Max/Skip paging; Author filter (two authors — use Cmd.Env GIT_AUTHOR_NAME/EMAIL or `-c user.name` via repo.Runner.Run); Grep literal with regex metacharacters; IgnoreCase; Since/Until with fixed GIT_AUTHOR_DATE/GIT_COMMITTER_DATE (state which date git filters on); Paths filter; Follow across a rename; ranges ("main..feat"); All; decorations (branch, tag, HEAD, remote-tracking); message with unicode (Türkçe), "%" sequences ("100%s done", "%H"), multi-paragraph body, trailing blank lines, a body line that is only "\x1e" or other control characters; timezone offsets (+03:00) preserved; hostile config repo (log.showSignature=true, format.pretty=oneline, log.decorate=full, log.date=relative, i18n.logOutputEncoding=ISO-8859-9, a .mailmap file) gives the same result; hostile revs ("--output=/tmp/gitpal-log-x", "-n1") refused with ArgInvalidRev and no file created; unknown rev → KindRefNotFound; CommitInfo; RecentMessages (n larger than history, unborn); a history of a few thousand commits parses quickly (build it fast with `git fast-import` through repo.Runner.Run with Stdin, or commit-tree in a loop — keep the test under ~3 s, skip under -short).

### Module: branch (spec 4.5)
Public API (use these names):
- `type Branch struct { Name string /* short: "main", "origin/main" */; Ref string /* "refs/heads/main" */; Remote bool; RemoteName string /* for remote-tracking branches, e.g. "origin" */; Hash string; Current bool; Upstream string /* short name; local branches only */; UpstreamGone bool; Ahead, Behind int; Subject string; CommitterDate time.Time }`
- `type BranchListOptions struct { Remotes bool /* also list remote-tracking branches */ }`
- `func (r *Runner) Branches(ctx context.Context, dir string, opts BranchListOptions) ([]Branch, error)` — `for-each-ref` with a NUL-separated explicit format (fields such as %(refname), %(refname:short), %(objectname), %(HEAD), %(upstream:short), %(upstream:track), %(symref), %(contents:subject), %(committerdate:iso-strict)); skip symbolic refs such as refs/remotes/origin/HEAD; parse %(upstream:track) ("[ahead 1, behind 2]", "[ahead 3]", "[behind 1]", "[gone]", ""). Careful: %(refname:short) can be ambiguous/abbreviated in odd ways (a local branch named "origin/x", core.warnAmbiguousRefs) — derive Name from the full ref yourself. For remote-tracking branches determine RemoteName robustly even when the remote name contains a slash (compare against the configured remotes) — document what you do.
- `func (r *Runner) CurrentBranch(ctx context.Context, dir string) (string, error)` — the branch name; "" when HEAD is detached; on an unborn branch the name of the branch to be born.
- `func (r *Runner) ValidateBranchName(ctx context.Context, dir, name string) error` — checkName + `git check-ref-format --branch`; returns *ArgError{Code: ArgInvalidBranch}. Beware that `--branch` EXPANDS "@{-1}"-style shortcuts: a name that git rewrites to something else is not a valid new name; "HEAD" is not acceptable either.
- `func SuggestBranchName(input string) string` — pure function turning free text into a valid branch name: lower case, Turkish letters transliterated (ç→c ğ→g ı→i İ→i ö→o ş→s ü→u, also their capitals), other non-ASCII letters dropped or reduced, whitespace/underscores/punctuation → "-", runs of "-" collapsed, "/" kept as a segment separator (so "feat/Yeni Özellik!" → "feat/yeni-ozellik"), each segment trimmed of "-" and ".", no "..", no trailing ".lock", no "@{", never starting with "-"; an input with nothing usable returns "". Property to test: for any non-empty result, `git check-ref-format --branch` accepts it (table of nasty inputs + a small deterministic generated set).
- `var BranchPrefixes = []string{"feat/", "fix/", "chore/", "docs/", "refactor/", "test/"}` — suggestions for the UI (spec: "Branch adı doğrulama ve öneri (örn. feat/…, fix/…)").
- `func (r *Runner) CreateBranch(ctx context.Context, dir, name, start string) error` — create without switching; start "" = HEAD. Validates the name first.
- `func (r *Runner) SwitchBranch(ctx context.Context, dir, name string) error` — `git switch`; switching to a name that exists only as a single remote-tracking branch creates the local tracking branch (git's default guess behaviour — make it explicit and config-independent: checkout.guess, checkout.defaultRemote).
- `func (r *Runner) CreateAndSwitch(ctx context.Context, dir, name, start string) error` — `git switch -c`.
- `func (r *Runner) RenameBranch(ctx context.Context, dir, oldName, newName string) error` — never overwrites an existing branch.
- `func (r *Runner) DeleteBranch(ctx context.Context, dir, name string, force bool) error` — force=false refuses unmerged branches (KindBranchNotMerged); force=true is `-D` (the M2 safety layer decides when that is allowed and backs up first — not your job). Deleting the checked-out branch must fail with a kind the UI can explain (declare a new kind if none fits).
- `func (r *Runner) MergedBranches(ctx context.Context, dir, into string) ([]string, error)` — local branches whose tip is reachable from `into` (empty = HEAD), excluding `into` itself and the current branch: the candidates for "merge edilmiş branch'leri toplu temizleme".
- `func (r *Runner) SetUpstream(ctx context.Context, dir, branch, upstream string) error` and `func (r *Runner) UnsetUpstream(ctx context.Context, dir, branch string) error`.
Requirements: every user-supplied name through checkName and after endOfOptions (verify each git subcommand you use accepts --end-of-options in git 2.30 — it was added in 2.24; if a subcommand misbehaves, use another safe form and document it). Neutralize config: branch.autoSetupMerge / branch.autoSetupRebase where it changes what you promise, branch.sort (pass an explicit --sort), column.ui, advice.*, checkout.guess, checkout.defaultRemote, push.default irrelevant.
Integration tests must include: list on unborn repo (empty, CurrentBranch "main"); list with several branches, Current flag; detached HEAD (no Current, CurrentBranch ""); remote-tracking list with origin/HEAD skipped; upstream + ahead/behind/gone; a local branch literally named "origin/main" next to the remote-tracking one; unicode branch names ("özellik/giriş"); create (from HEAD, from a start point, existing → KindBranchExists, bad start → KindRefNotFound-like); hostile names refused with ArgInvalidBranch and no side effect ("--force", "-D", "a..b", "@{-1}", "HEAD", "x.lock", "a b", "", "refs/heads/x" — decide and document); switch (clean, dirty with conflicting change → KindDirtyWorktree and worktree untouched, nonexistent → KindRefNotFound, remote-only name creates tracking branch, ambiguous between two remotes → error); create-and-switch; rename (ok, target exists → error, current branch); delete merged / unmerged / forced / current branch / nonexistent; MergedBranches; set/unset upstream; hostile config repo.

### Module: remote — fetch / pull / push (spec 4.4, 4.11 list only, 7.2 rules 1, 2, 5)
Public API (use these names):
- `type Remote struct { Name, FetchURL, PushURL string }` — URLs are passed through redact(): gitpal never hands embedded credentials to a UI or log. `func (r *Runner) Remotes(ctx context.Context, dir string) ([]Remote, error)` — robust to remote names containing dots or slashes; decide between `remote get-url` and reading config and document why (insteadOf rewriting).
- `type FetchOptions struct { Remote string /* empty = git's default remote */; All bool; Prune bool }`, `func (r *Runner) Fetch(ctx context.Context, dir string, opts FetchOptions) error`.
- `type PullStrategy string`: PullMerge "merge", PullRebase "rebase", PullFFOnly "ff-only" (the values of the pull.strategy setting in gitpal's config; do NOT import the config package). `type PullOptions struct { Strategy PullStrategy /* empty = PullFFOnly, the safest */; Remote, Branch string /* optional explicit source; both or neither */ }`, `type PullResult struct { Before, After string /* HEAD before and after */; Updated bool }`, `func (r *Runner) Pull(ctx context.Context, dir string, opts PullOptions) (PullResult, error)`.
  - The strategy must win over the user's git config (pull.rebase, pull.ff, merge.ff, branch.<n>.rebase, rebase.autoStash, merge.autoStash): pass explicit flags (`--ff-only`; `--no-rebase --ff --no-edit`; `--rebase`), and `--no-autostash` so nothing is stashed behind the user's back (the M2 safety layer handles dirty trees). Prove it with hostile config tests.
  - When pull fails and the repository is left with unresolved conflicts (unmerged index entries / MERGE_HEAD / rebase directories — inspect the repository, do not parse output), the returned *Error must have Kind KindConflict. Diverged with ff-only → KindDiverged, dirty tree in the way → KindDirtyWorktree, no upstream → KindNoUpstream, detached HEAD → KindDetachedHead.
- `type PushOptions struct { Remote string /* empty = the branch's configured push/upstream remote, else "origin" */; Branch string /* local branch; empty = current */; SetUpstream bool; ForceWithLease bool; ExpectedRemote string /* optional: the remote branch must still be at this commit */ }`
- `type PushStatus string`: PushNew, PushFastForward, PushForced, PushUpToDate. `type PushResult struct { Remote, Branch, RemoteBranch string; Status PushStatus; Before, After string /* remote ref old/new hash when known */ }`
- `func (r *Runner) Push(ctx context.Context, dir string, opts PushOptions) (PushResult, error)`:
  - there is NO way to request a plain `--force` (spec 7.2 rule 2). ForceWithLease uses `--force-with-lease=<ref>[:<expect>]` plus `--force-if-includes` (added in git 2.30 — confirm).
  - push exactly one branch with an explicit refspec (refs/heads/<local>:refs/heads/<remote-branch>): user config such as push.default=matching/nothing, push.followTags, remote.<n>.push, remote.<n>.mirror must not make it push anything else. The remote branch name is the upstream's branch name when the branch tracks a branch on that same remote, otherwise the local name — document it.
  - use `--porcelain` and parse stdout (lines "<flag>\t<from>:<to>\t<summary>[ (<reason>)]", flags ' ' '+' '-' '*' '!' '='; first line "To <url>" — redact it) to fill PushResult and to set the error Kind from the machine-readable reason: "stale info" → KindStaleLease, "fetch first"/"non-fast-forward" → KindRejected, "[remote rejected]" → KindRemoteDeclined. Check how the exit status behaves with --porcelain across versions and do not rely on it alone.
  - detached HEAD with empty Branch → an *Error with Kind KindDetachedHead before pushing; unknown remote → KindNoRemote.
- `func (r *Runner) Upstream(ctx context.Context, dir, branch string) (name string, ok bool, err error)` — e.g. "origin/main"; ok=false when none is configured (branch "" = current).
- `func (r *Runner) AheadBehind(ctx context.Context, dir, local, upstream string) (ahead, behind int, err error)` — `rev-list --left-right --count`; M2 uses it for "push öncesi ahead/behind kontrolü".
Requirements: every network command through networkCmd (NetworkTimeout); prove it with a unit test using fakeRunner("report") from runner_test.go if you can observe it, otherwise by structure. Names via checkName (ArgInvalidRemote / ArgInvalidBranch / ArgInvalidRev) and after endOfOptions. Credentials must never appear in returned errors, PushResult or Remotes(): test with a remote URL such as "https://user:s3cr3t-token@127.0.0.1:1/x.git" (connection refused immediately → KindRemoteUnreachable; assert the secret is absent from err.Error(), from Localize(TR/EN) and from the Event the observer sees). Keep GIT_TERMINAL_PROMPT=0 behaviour. Known limitation to note, not solve: ssh may prompt on /dev/tty.
Integration tests (bare origin via gittest.NewBareRepo, two clones via gittest.Clone; the first clone must push an initial commit): Remotes (none, one, separate pushurl, credentials redacted, name with dot); Fetch (updates remote-tracking ref, Prune removes a deleted branch, All with two remotes, unknown remote → error kind); Pull ff-only (fast-forward ok with Before/After/Updated; already up to date; diverged → KindDiverged and HEAD unchanged); Pull merge (merge commit created without an editor; conflict → KindConflict and status shows merge in progress); Pull rebase (linear history; conflict → KindConflict with rebase in progress); Pull with dirty conflicting file → KindDirtyWorktree and file untouched; Pull no upstream; Pull detached; hostile config (pull.rebase=true with Strategy merge, pull.ff=only with Strategy merge on diverged history, rebase.autoStash=true with dirty tree must NOT stash); Push new branch with SetUpstream (Upstream() then reports it, PushNew); Push fast-forward (PushFastForward, Before/After); up to date; rejected non-ff → KindRejected and remote unchanged; ForceWithLease success (PushForced); ForceWithLease refused when the remote moved without us fetching → KindStaleLease and remote unchanged; ExpectedRemote mismatch → KindStaleLease; server-side pre-receive hook in the bare repo that exits 1 → KindRemoteDeclined (skip on Windows); detached HEAD; no remote; hostile names; hostile push config (push.default=matching with a second local branch that must NOT be pushed, push.followTags=true with a tag that must not be pushed); branch tracking an upstream with a different name; AheadBehind (0/0, ahead, behind, diverged, bad ref); Upstream (set, unset, detached).
